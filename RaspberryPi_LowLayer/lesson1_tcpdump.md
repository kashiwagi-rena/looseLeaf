# Lesson 1: tcpdump で実物を見る

## ゴール

流れているパケットを観察できる。

## 準備

Lesson 0 で使った `tcpdump` を、もう少し詳しく見ていく。

```bash
sudo tcpdump -i eth0 -n -e -c 10 icmp
```

- `-i eth0`: 観察するインターフェースを指定
- `-n`: ホスト名やポート名を名前解決せず、数字のまま表示（速いし分かりやすい）
- `-e`: Ethernetヘッダ（MACアドレスなど）も表示
- `-c 10`: 10パケット受信したら終了
- `icmp`: ICMP（pingで使われるプロトコル）だけに絞るフィルタ

## 実験

### 1. ICMP（ping）を見る

```bash
# ターミナル1
sudo tcpdump -i eth0 -n -e icmp

# ターミナル2
ping -c 5 <相手のIPアドレス>
```

出力の1行が1パケット。送信元・宛先のMACアドレス・IPアドレスと、ICMPの種類（echo request / echo reply）が見えるはず。

### 2. UDP を見る

参考記事のポート `4000` を使ってみる。

```bash
# ターミナル1（Raspberry Pi側）
sudo tcpdump -i eth0 -n -e udp port 4000

# ターミナル2（別PC側、ncがあれば）
echo "hello" | nc -u <PiのIPアドレス> 4000
```

`nc`（netcat）がない場合は、Lesson 3 で作るPythonスクリプトで代用できるので、ここでは一度スキップしてよい。

### 3. 自分以外のトラフィックも見てみる

```bash
sudo tcpdump -i eth0 -n -c 20
```

フィルタなしで動かすと、ネットワーク上を流れている他のパケット（ARP、DHCPなど）も見える。見慣れないプロトコル名が出てきたら、それも調べてみる。

## セキュリティ面の注意

- フィルタなしで `tcpdump` を動かすと、自分宛て以外の通信も見えることがある（特にハブ環境やミラーポート）。自分が管理するネットワークでのみ行う
- 他人の通信内容（特に暗号化されていない通信のペイロード）を覗く行為は、プライバシー・法律の観点で問題になりうる。ヘッダの観察にとどめる

## 自分の言葉で説明してみる

- `tcpdump` で見ているのは、ネットワークスタックのどの段階のパケットか（Netfilterやソケットより手前か後か）
- ICMPとUDPの出力の違いは何か
