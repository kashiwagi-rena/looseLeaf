# Lesson 0: 通信は封筒の入れ子

## ゴール

Ethernet / IP / UDP(TCP) / アプリデータの4層を、封筒の例えで説明できる。

## 封筒の例え

手紙を送る場面で考える。

1. 手紙の本文を書く（アプリのデータ）
2. 封筒に入れて、宛先の「部署・担当者名」を書く（これが UDP/TCP）
3. それを別の封筒に入れて、宛先の「住所」を書く（これが IP）
4. さらにそれを、配達員が運ぶ箱に入れて、「次の配達所」を書く（これが Ethernet）

パケットも同じで、データに、外側から順にヘッダ（宛先などの情報）を付けていく。

| 層 | 宛先の書き方 | 役割 |
|---|---|---|
| Ethernet | MACアドレス | 同じネットワーク内の、次の機器まで届ける |
| IP | IPアドレス | ネットワークをまたいで、相手のマシンまで届ける |
| UDP/TCP | ポート番号 | マシンの中の、どのアプリに渡すかを決める |
| アプリのデータ | なし | HTTPなどの本文 |

参考記事の「UDP :4000」は、「ポート番号4000のアプリ宛ての UDP 通信」という意味になる。

受け取る側はこの封筒を外側から1枚ずつ開けていく。「XDP → ネットワークスタック → Netfilter → ソケット」という話は、どの段階まで開けてから捨てるか、という話になる。早く捨てるほど、開ける手間が省ける。

## 実験

Raspberry Pi のターミナルで試す。

```bash
ip addr
```

出力から、自分の IPアドレス（`inet` の行）と MACアドレス（`link/ether` の行）を探す。インターフェース名は `eth0`（有線）か `wlan0`（無線）が多い。

次に、別の機器（PC など）に ping を打ちながら、中身を覗く。ターミナルを2つ開く。

```bash
# ターミナル1: 観察する（-e でMACアドレスも表示）
sudo tcpdump -i eth0 -n -e -c 10 icmp

# ターミナル2: 通信を発生させる
ping -c 3 <自分のPCのIPアドレス>
```

`eth0` の部分は、`ip addr` で確認したインターフェース名に置き換える。

## セキュリティ面の注意

- `tcpdump` は他人の通信も見えてしまう道具。自分が管理するネットワークだけで使う
- `sudo` で動かしているのは、権限が必要だから。コマンドの中身が分からないまま実行しない
