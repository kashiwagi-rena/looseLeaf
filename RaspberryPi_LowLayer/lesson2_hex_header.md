# Lesson 2: ヘッダを手で読む

## ゴール

16進数のダンプから、IPアドレスやポート番号を自分の手で読める。

## 準備

`tcpdump` にペイロードまで含めた16進ダンプを出させる。

```bash
sudo tcpdump -i eth0 -n -e -x -c 1 udp port 4000
```

- `-x`: パケットの内容を16進数で表示

別のターミナルから送信して、1パケットだけ捕まえる。

```bash
echo "hello" | nc -u <PiのIPアドレス> 4000
```

## ヘッダの構造

### Ethernetヘッダ（先頭14バイト）

| バイト位置 | 内容 | サイズ |
|---|---|---|
| 0-5 | 宛先MACアドレス | 6バイト |
| 6-11 | 送信元MACアドレス | 6バイト |
| 12-13 | EtherType（`0x0800` ならIPv4） | 2バイト |

### IPv4ヘッダ（Ethernetヘッダの後、先頭20バイト以上）

| バイト位置（IPヘッダ先頭からの相対） | 内容 |
|---|---|
| 0 | バージョン(4bit) + IHL(4bit)。IHLは「IPヘッダの長さ ÷ 4」 |
| 9 | プロトコル番号（`17` ならUDP、`6` ならTCP、`1` ならICMP） |
| 12-15 | 送信元IPアドレス |
| 16-19 | 宛先IPアドレス |

IHL（Internet Header Length）が重要。多くの解説では「IPヘッダは20バイト」と書かれるが、オプションが付くと20バイトより長くなる。固定の20バイトで決め打ちすると、オプション付きパケットで位置がずれる。

### UDPヘッダ（IPヘッダの後、8バイト）

| バイト位置（UDPヘッダ先頭からの相対） | 内容 |
|---|---|
| 0-1 | 送信元ポート |
| 2-3 | 宛先ポート |
| 4-5 | UDP長 |
| 6-7 | チェックサム |

## 実験

1. `tcpdump -x` の出力から、Ethernetヘッダの12-13バイト目（EtherType）が `0800` になっていることを確認する
2. IPヘッダの先頭バイトを見て、IHLを計算する（例: `45` なら `4`=バージョン, `5`=IHL → `5*4=20`バイト）
3. IPヘッダ9バイト目（プロトコル番号）が `11`（16進数で17 = UDP）になっていることを確認する
4. 送信元・宛先IPアドレスの4バイトを、10進数のIPアドレスに変換してみる（`192.168.1.10` のような形）
5. UDPヘッダの宛先ポート2バイトが `0fa0`（10進数で4000）になっていることを確認する
