## 1. クラウドの概念(試験の約24%)

| 項目 | 一言 | 印 |
|---|---|---|
| **責任共有モデル** | AWS =クラウド**「の」**セキュリティ(物理・ハイパーバイザー)/ 顧客 =クラウド**「における」**セキュリティ(データ・IAM・設定) | 🟡 |
| 責任範囲の違い | **EC2**:OSパッチも顧客 → **RDS**:OSはAWS → **Lambda**:コードと権限だけ顧客。サービスで境目が変わる | 🟡 |
| **俊敏性**(Agility) | **すばやく**用意して試せる。失敗したらすぐ消せる | 🟡 |
| **伸縮性**(Elasticity) | 負荷に合わせて**自動で増減**できる | 🟢 |
| **高可用性** | 止まりにくい(複数AZなど) | 🟡 |
| **耐障害性** | 一部が壊れても動き続ける | 🟡 |
| **CapEx → OpEx** | 初期投資(買う)→ 従量課金(借りる)。ただし「必ず安くなる」は誤り | 🟢 |
| **Region / AZ / エッジ** | Region =地域、AZ =Region内の分離されたデータセンター群、エッジ = CloudFront の各地の配信拠点 | 🟢 |
| **Well-Architected 6本柱** | 運用上の優秀性 / セキュリティ / **信頼性** / パフォーマンス効率 / コスト最適化 / 持続可能性 ※**俊敏性は柱ではない** | 🟡 |
| **CAF**(キャフ) | クラウド**導入**を組織で進める計画ガイド。6視点:ビジネス・人材・ガバナンス・プラットフォーム・セキュリティ・オペレーション | 🟡 |
| **移行の6つのR** | **Rehost**=そのまま移す / **Replatform**=少し最適化 / **Repurchase**=別製品に買い替え / **Refactor**=作り直し / **Retire**=廃止 / **Retain**=現状維持 | 🟡 |
| **Snowball**(スノーボール) | ペタバイト級のデータを**物理デバイスで運ぶ**(Snow Family)。提供状況は公式で確認 | 🟢 |

## 2. セキュリティとコンプライアンス(試験の約30%)

### 2-1. 権限(IAM)

| 項目 | 一言 | 印 |
|---|---|---|
| **IAMユーザー** | **人**のID | 🟢 |
| **IAMロール** | **サービス**(EC2・Lambda など)や一時的な権限用。アクセスキーをコードに埋め込まない | 🟡 |
| **IAMポリシー** | 「誰が・何を・してよいか」を書いた**権限のJSON文書** | 🟡 |
| **ルートユーザー** | 全権限。**MFAを有効化**し、日常作業には使わない | 🟢 |
| **MFA** | パスワード+もう1つの確認(多要素認証) | 🟢 |

### 2-2. 記録・監査・診断

| サービス | 一言 | 決め手のキーワード | 印 |
|---|---|---|---|
| **CloudTrail**(クラウド・トレイル) | **誰が**・いつ・どの操作をしたかの**足跡** | 誰が / 操作の記録 | 🔴 |
| **Config**(コンフィグ) | リソースの**設定がどう変わったか**、ルールに合うか | 設定の履歴 / 準拠 | 🔴 |
| **CloudWatch**(クラウドウォッチ) | **今の状態**の監視(CPU など)とアラーム | 監視 / メトリクス | 🟡 |
| **Trusted Advisor**(トラステッド・アドバイザー) | AWS が**自動診断**して改善点を助言する(人間ドック)。コスト・セキュリティ・耐障害性・性能・上限 | AWSが診断 / 助言 | 🔴 |
| **Artifact**(アーティファクト) | **AWS自身の**証明書類・認証レポート(SOC・ISOなど)をDL | AWSの証明書類 | 🔴 |

> **CloudTrail の注意**:Event history は**直近90日分のみ**。長期保管するには **Trail を作成して S3 に保存**する。

### 2-3. 脅威の検知・防御・暗号化

| サービス | 一言 | 決め手のキーワード | 印 |
|---|---|---|---|
| **GuardDuty**(ガードデューティ) | アカウント内の**不審な動き**を見張る | 不審な通信 / 脅威検知 | 🔴 |
| **Inspector**(インスペクター) | EC2 などの**脆弱性**を検査 | 既知の弱点 / スキャン | 🔴 |
| **Macie**(メイシー) | **S3 の中の個人情報**を探す | S3 + 個人情報 | 🔴 |
| **Shield**(シールド) | **DDoS** 攻撃から守る(盾) | DDoS / 大量アクセス | 🟢 |
| **WAF**(ワフ) | **Web攻撃**(SQLインジェクション、XSS)を防ぐ | Web攻撃 | 🟢 |
| **KMS**(ケー・エム・エス) | **暗号鍵**の作成・管理 | 鍵 | 🟢 |

### 2-4. ネットワークのファイアウォール

| | **セキュリティグループ(SG)** | **ネットワークACL(NACL)** | 印 |
|---|---|---|---|
| 単位 | **インスタンス** | **サブネット** | 🔴 |
| ステート | **ステートフル**(戻りは自動許可) | **ステートレス**(戻りもルールが必要) | 🔴 |
| ルール | **許可のみ** | **許可と拒否** | 🔴 |
| たとえ | 顔を覚えているフロント係 | 記憶がない警備員 | |

## 3. クラウドテクノロジーとサービス(試験の約34%)

### 3-1. コンピュート

| サービス | 一言 | 印 |
|---|---|---|
| **EC2**(イーシーツー) | 仮想サーバー。OSから自分で管理 | 🟢 |
| **Lambda**(ラムダ) | **コード**をイベントで実行。サーバー管理不要、実行時間課金 | 🟢 |
| **Auto Scaling**(オート・スケーリング) | 負荷に応じて **EC2 の台数を自動で増減**(店長) | 🔴 |
| **ELB**(イー・エル・ビー) | アクセスを複数台に**振り分ける**(案内係) | 🔴 |
| **Fargate**(ファーゲート) | **コンテナ**をサーバー管理なしで実行 | 🔴 |
| **ECS**(イー・シー・エス) | AWS独自のコンテナ管理(指揮係) | 🟡 |
| **EKS**(イー・ケー・エス) | **Kubernetes** をAWSが管理(指揮係) | 🟡 |
| **Elastic Beanstalk**(ビーンストーク) | **コードを渡すだけ**で環境構築・デプロイ・スケーリングを自動化 | 🔴 |
| **Lightsail**(ライトセイル) | **軽量版**。小規模サイトを簡単・分かりやすい料金で | 🟡 |

> **コンテナ**:アプリと必要な部品を**1つの箱に詰めたもの**(お弁当箱)。

### 3-2. ストレージ

| サービス | 種類 | たとえ | 印 |
|---|---|---|---|
| **S3**(エス・スリー) | **オブジェクト** | Google Drive のようなネット上の保管庫 | 🟢 |
| **EBS**(イー・ビー・エス) | **ブロック** | PCの**内蔵ディスク**(1台のEC2用) | 🟡 |
| **EFS**(イー・エフ・エス) | **ファイル** | **共有フォルダ**(複数のEC2から同時に使える) | 🔴 |

**S3 のストレージクラス**(アクセス頻度が下がるほど、安く・取り出しは遅く)

| クラス | 一言 | 印 |
|---|---|---|
| **Standard** | 頻繁にアクセス | 🟡 |
| **Intelligent-Tiering** | パターン不明なら**自動で最適化** | 🔴 |
| **Standard-IA / One Zone-IA** | **低頻度**だが即時取得(One Zone は1AZのみで耐障害性が低い) | 🔴 |
| **Glacier**(グレイシャー) | アーカイブ(氷河=凍らせて保管) | 🔴 |
| **Glacier Deep Archive** | **最安**。取り出しに数時間 | 🔴 |

### 3-3. データベース

| サービス | 一言 | 印 |
|---|---|---|
| **RDS**(アール・ディー・エス) | **業務データ**の記録用(SQL・表形式)。AWSが管理 | 🟢 |
| **DynamoDB**(ダイナモ・ディー・ビー) | **NoSQL**。キーと値で、ミリ秒の高速。サーバーレス | 🟢 |
| **Redshift**(レッドシフト) | **分析用**のデータウェアハウス。大量データを集計 | 🔴 |
| **ElastiCache**(エラスティキャッシュ) | **メモリ**にキャッシュして高速化 | 🟡 |

| | **Multi-AZ** | **リードレプリカ** | 印 |
|---|---|---|---|
| 目的 | **止まらない**(高可用性) | **読み取りを速く**(性能) | 🔴 |
| 動き | 障害時に**自動で切り替わる** | 読み取り**専用のコピー** | |
| たとえ | **予備の本店** | **閲覧用のコピー帳簿** | |

### 3-4. ネットワーク

| サービス | 一言 | 印 |
|---|---|---|
| **VPC**(ブイ・ピー・シー) | AWS上の**自分専用のネットワーク** | 🟡 |
| **IGW**(インターネットゲートウェイ) | VPCの**正面玄関**。**双方向**。パブリックサブネット用 | 🔴 |
| **NAT ゲートウェイ** | プライベートから**外へ出るだけ**の**代表電話**。外から直接は入れない | 🔴 |
| **Route 53**(ルート・フィフティスリー) | **DNS**(名前 → IP) | 🟢 |
| **CloudFront**(クラウドフロント) | **CDN**。世界各地にキャッシュして配信(各地の支店) | 🟢 |
| **Direct Connect**(ダイレクト・コネクト) | オンプレとの**専用線** | 🟡 |
| **VPN**(ブイ・ピー・エヌ) | 暗号化したインターネット経由の接続 | 🟡 |

### 3-5. 統合・管理・操作

| サービス | 一言 | 印 |
|---|---|---|

| **AWS CLI**(シー・エル・アイ) | **コマンド**で操作。スクリプトで自動化 | 🟡 |
| **AWS SDK**(エス・ディー・ケー) | **プログラムのコード**から呼び出す | 🟡 |
| **AWS Health**(ヘルス) | **自分のリソース**に影響する障害・メンテナンスの通知 | 🟡 |
| **Marketplace**(マーケットプレイス) | サードパーティのソフトを購入できる**市場** | 🟢 |

## 5. 混同しやすいペア(最優先で復習)

| 迷ったら | A | B | 判断ルール |
|---|---|---|---|
| 🔴 **CloudTrail vs Config** | 足跡(**誰が**) | 設定の履歴(**モノの状態**) | 「誰が」→ Trail、「設定の変化・準拠」→ Config |
| 🔴 **SG vs NACL** | インスタンス・許可のみ・ステートフル | サブネット・許可/拒否・ステートレス | 「ステートレス」「拒否ルール」→ NACL |
| 🔴 **IGW vs NAT** | 正面玄関(双方向) | 代表電話(内→外のみ) | 「プライベートが外へ出たい」→ NAT |
| 🔴 **SQS vs SNS** | 溜める(郵便受け) | 一斉通知(放送) | 「溜めて後で処理」→ SQS、「複数宛先へ通知」→ SNS |
| 🔴 **Multi-AZ vs リードレプリカ** | 止まらない | 読み取りを速く | 「障害対策」→ Multi-AZ、「読み取りが重い」→ レプリカ |
| 🔴 **GuardDuty / Inspector / Macie** | 不審な動き | EC2の脆弱性 | **対象**で区別。Macie は S3 の個人情報 |
| 🟢 **Shield vs WAF** | DDoS(大量アクセス) | Web攻撃(中身を見て防ぐ) | 名前に「Web」→ WAF |
| 🔴 **Budgets / Cost Explorer / Pricing Calculator** | 予算超過の**アラート** | 過去の**分析** | 見積もりは Pricing Calculator |
| 🟡 **Fargate / Lambda / EC2** | コンテナ実行(管理不要) | コード実行(管理不要) | 「コンテナ」→ Fargate、「コード」→ Lambda |
| 🔴 **Beanstalk vs CloudFormation** | コードを渡すだけ | 設計図を自分で書く | 「コードを渡すだけ」→ Beanstalk |
| 🔴 **S3 / EBS / EFS** | オブジェクト | ブロック / ファイル | 「共有」→ EFS、「内蔵ディスク」→ EBS |
| 🔴 **ELB vs Auto Scaling** | 振り分け(案内係) | 台数の増減(店長) | 両方セットで使う |
